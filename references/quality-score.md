# 好用度：10 分制加权合成

好用度回答“这个 Skill 本身做得怎么样”，跟评估者本机的设备、是否已安装无关。它由 8 个维度加权合成，共用计算规则见 [scoring-rubric.md](scoring-rubric.md)。

## 八个维度与权重

| 维度 | 权重 | 打分依据 |
| --- | ---: | --- |
| 风险值 | 2.0 | [risk-score.md](risk-score.md)，0—10 分，分数越低越好 |
| 公开关注度 | 1.5 | 本文件下方“公开关注度分档” |
| 安装复杂度 | 1.25 | [installation-score.md](installation-score.md)，0—10 分，分数越低越好 |
| 可验证性 | 1.25 | 本文件下方“可验证性分档” |
| 任务复杂度 | 1.25 | [task-complexity.md](task-complexity.md)，0—10 分，分数越低越好 |
| 额外涉及费用 | 1.75 | 本文件下方“额外涉及费用分档” |
| Token 消耗 | 0.5 | [token-score.md](token-score.md)，0—10 分，分数越低越好 |
| Skill 调用准确性 | 0.5 | 本文件下方“调用准确性分档” |

八项权重加总固定为 10。排序逻辑：风险值后果最重，排第一；公开关注度是安全性、需求度、信任度的复合信号，和安装复杂度并列第二档；可验证性、任务复杂度权重居中；额外涉及费用因为用户对“要不要花钱”天然敏感，单独给到较高权重；Token 消耗通常可控可预算，权重较低；Skill 调用准确性影响体验但出问题通常能发现能纠正，权重最低。

## 计算方法

“风险值”“安装复杂度”“任务复杂度”“Token 消耗”四项直接复用对应文件算出的 0—10 分（分数越低越好），先换算成 0—2 的“好坏分”，公式：

```
好坏分 = 2 × (10 − 原始 0—10 分) ÷ 10
```

“公开关注度”“可验证性”“额外涉及费用”“Skill 调用准确性”四项直接按下方分档表取 0—2 的好坏分，不需要换算。

每个维度的好坏分乘以（权重 ÷ 2），八项加总即为好用度（0—10，保留一位小数）。

## 公开关注度分档（0—2）

| 好坏分 | 判断 |
| --- | --- |
| 2.0 | 高关注：有权威榜单认证，或 Star/Fork 数明显领先同类项目，且近期仍在增长 |
| 1.3 | 中等关注：有一定 Star/Fork 积累，或有小范围真实使用反馈，规模不算突出 |
| 0.6 | 低关注/起步：Star/Fork 很少，缺乏公开使用反馈，或项目刚起步 |
| 1.0 | 未验证：找不到可核验的公开数据，按中性分处理，不判定优劣 |

## 可验证性分档（0—2）

| 好坏分 | 判断 |
| --- | --- |
| 2.0 | 充分：文档、更新记录、Issue 处理、真实案例比较完整，能相互印证 |
| 1.0 | 一般：有基本文档和更新记录，但测试、案例或 Issue 处理不够充分，或部分依赖已停更 |
| 0 | 不足：文档缺失、长期不更新，或没有可查的真实使用案例 |

## 额外涉及费用分档（0—2）

对应 [installation-score.md](installation-score.md) 的“额外涉及费用写法”：

| 好坏分 | 对应写法 |
| --- | --- |
| 2.0 | 无新增费用 / 核心免费 |
| 1.5 | 核心免费，扩展功能可能付费 |
| 1.0 | 核心路径有一项必付或按量计费 |
| 0.3 | 多项持续付费 |
| 1.0 | 代码公开，暂未发现直接费用，使用许可未验证（按中性分处理） |
| 1.0 | 价格未验证（按中性分处理） |

## 调用准确性分档（0—2）

对应 [invocation-accuracy.md](invocation-accuracy.md) 的定性结果：

| 好坏分 | 对应结果 |
| --- | --- |
| 2.0 | 较准确 |
| 1.0 | 偏宽 或 偏窄 |
| 0.5 | 无法判断 |

## 报告要求

- 指标表展示八项的评估结果（新增“可验证性”一行，位置放在“公开关注度”之后）；风险值、安装复杂度、任务复杂度、Token 消耗这四项只写等级词（比如“中等”“很简单”“低”），不写 0—10 原始分，原始分只进过程 JSON 的 `raw10` 字段；
- 好用度这个合成分数由渲染器自动算出，单独放一行“好用度：X.X/10。”，加在“这个 Skill 好用吗”一行摘要最前面并高亮；`quality_summary` 只写“完整度……”这段描述本身，不用自己写“好用度”这几个字或数字；不需要单独展开八项权重拆解，用户报告不出现具体权重数字；
- 未验证项按对应分档表的“未验证/中性”档处理，不打 0 分，也不假装精确。

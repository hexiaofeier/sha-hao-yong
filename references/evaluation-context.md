# 固定常规任务

本文件规定跑分前如何锁定固定常规任务。任务复杂度、Token 消耗和风险值都使用它；安装复杂度始终按从零安装计算，好用度和适合度均不受评估者本机是否已经安装目标对象影响，评分时默认候选对象已完整安装配置。

## 先锁定固定常规任务

固定常规任务是目标 Skill 被正确安装后，普通用户最常用的一次完整任务。

从以下证据依次抽象：

1. 官方定位和默认入口；
2. README 的快速开始或默认工作流；
3. 主要交付物；
4. 官方示例中反复出现的典型用法。

固定常规任务必须写清：

| 字段 | 内容 |
| --- | --- |
| 目标 | 这次任务解决什么问题 |
| 输入 | 用户提供什么 |
| 工作量 | 一次任务涉及多少资料、来源、工具、媒体或修改轮次 |
| 输出 | 最终得到什么 |
| 来源 | 依据哪份官方材料抽象 |

选择规则：

- 不取只验证“能跑”的最轻演示；
- 不取所有可选功能同时开启的极端用法；
- 官方没有规定精确数量时，写清有边界的常规工作量，不临时发明固定条数；
- 个性化评估也沿用固定常规任务计算任务复杂度、Token 和风险值；用户需求只进入推荐程度里的目标匹配和交付匹配；
- 同一 Skill 再次评估时优先复用上次过程 JSON 中的固定常规任务；
- 核心定位或默认工作流发生变化后才能更换。更换时把 `changed` 写为 `true`，并填写 `change_reason`。

## 安装状态不参与评分

评估过程中不需要检测候选对象是否已经安装在当前设备上，也不需要询问用户是否结合当前设备判断。原因：

- 安装复杂度始终按“一台满足基本要求、尚未安装目标对象的设备”从零安装、配置和维护计算，评估者本机是否已经装过，不改变这个数字；
- 好用度和适合度的每一项评分，都假设候选对象已经完整安装并配置到位，不因为某个可选功能尚未安装而扣分；
- 安装这件事本身的负担，已经完整体现在好用度的“安装复杂度”这一项里，不在别处重复计分。

如果评估者恰好在本机试用过候选对象、掌握了额外的真实反馈，可以把这些发现写进对应指标的判断依据里作为佐证，但不得因为“本机已装/未装”单独调整任何一项分数。

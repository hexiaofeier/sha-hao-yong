# 定量评分共用规则

本文件适用于安装复杂度、任务复杂度、Token 消耗、风险值和推荐程度。各指标评什么、怎样分级，仍以对应 Reference 为准。

## 计算

- 先按 [evaluation-context.md](evaluation-context.md) 锁定固定常规任务，不拿最轻演示或可选的极端功能代替典型用法；
- 各维度按最高分的 `0%、25%、50%、75%、100%` 取值，中间状态可保留一位小数；
- 不同用法差异明显时，固定常规任务仍只取官方主要用途；可选用法单列说明，不混入主分；
- 未确认项不补 0，写已知区间或 `未验证`；
- 只看公开文件时写“根据公开文件估算”，实际运行后才写“试跑估算”或“实测”。
- 安装复杂度始终按从零安装计算，跟评估者本机是否已安装无关。

## 报告

- 安装复杂度、任务复杂度、Token 消耗、风险值这四项在指标表里只显示等级（比如“中等”“很简单”“低”），不显示自身的 0—10 原始分；原始分只写进过程 JSON 的 `recommendation.quality.dimensions`，用于好用度计算；
- 好用度、适合度、推荐度这三个合成分数要显示具体数字：好用度放进“这个 Skill 好用吗”的一行摘要，适合度放进“这个 Skill 适合你吗”的顶部结论，推荐度放在结论概述的主分数，三处都由渲染器自动算出并高亮显示；
- 内部过程文件保留固定常规任务、好用度 8 个维度和适合度 2 个维度的分数与理由，好用度、适合度、推荐度和等级都由渲染器自动算出，不手填；
- 费用、Token、风险、质量和推荐程度分别判断，不互相替代；
- 分数越低或越高只表示该指标本身，不自动推出“好用”“安全”或“值得安装”。
